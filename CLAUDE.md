# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The marketing website for **Neucent Technologies** (neucenttechnologies.com), an IT software company building web apps, mobile apps and AI products. It is a plain static site plus one PHP script, and **the repo root is uploaded as-is to the web root** of an Apache/PHP host that has **no WordPress**. It replaced an earlier crawled mirror of a WordPress site (recoverable from git history and the GitHub remote).

**Owner's content rules:** every word, layout and image must be original to Neucent. Nothing copied from other sites (ongraph.com was inspiration only), **no copyright notice** anywhere, and no invented claims such as awards, client counts, statistics or testimonials.

## Commands

- **Build** (Node 16+, no dependencies): `node tools/build.js`. Run it after *any* change under `src/` and after editing `assets/css/main.css` or `assets/js/main.js`, because the build also re-hashes the `?v=` cache-busting query on those two files.
- **Preview**: `python -m http.server 8000` from the repo root, then http://localhost:8000. Static only: PHP does not run, so the contact form's submit does nothing there.
- **Test the PHP form**: there is no PHP install on this machine. Run WordPress Playground purely as a PHP runtime: `npx @wp-playground/cli@latest server --mount-dir <repo path> /wordpress/nt --port=9401`, then POST to `http://127.0.0.1:9401/nt/contact-us/send.php`. Use a temporary, git-ignored `config.php` with a `sqlite:/tmp/...` DSN (the handler supports SQLite as well as MySQL) and delete it afterwards. `mail()` cannot be exercised this way.
- There is no test suite or linter. `node --check <file>` validates the JS, and the `php-parser` npm package (installed outside the repo) can syntax-check PHP.
- `git` is not on the PATH of the PowerShell tool in this environment.

## Architecture

- **The HTML at the repo root is generated.** `tools/build.js` turns `src/` into `index.html`, `services/index.html`, `ai-solutions/index.html`, `our-work/index.html`, `school-management-system/index.html`, `about-us/index.html`, `contact-us/index.html`, `404.html`, `sitemap.xml`, `robots.txt` and `assets/img/favicon.svg`. The generated files are committed on purpose (upload the root as it is). **Edit `src/`, never the generated HTML**, or the next build overwrites the change.
- `src/content.js` holds the copy as data (services, AI capabilities, process, FAQs, tech stack, industries, hire roles, company `timeline`, case-study `projects`, `testimonials`, form options). To add a project to the Our Work page, add an object to `projects` (and optionally a matching `testimonials` entry whose `project` is the same slug); `src/site.js` holds company details (email, phone, WhatsApp, socials, canonical URL) and hides any optional value left as `''`; `src/pages.js` holds one function per page; `src/layout.js` is the shared head, header and footer and the `esc()` HTML escaper; `src/icons.js` is the inline-SVG icon set. Page-specific prose that is not data (hero text, About copy) is written directly in `src/pages.js`.
- **URLs are clean directory URLs with root-absolute asset paths** (`/assets/...`, `/services/`). The slugs `about-us` and `contact-us` were kept from the old site so existing inbound links still work. `about-us`/`contact-us` are hard-coded in `layout.js` (nav and footer), `pages.js` (CTAs) and `tools/build.js` output paths; rename them together.
- **Project screenshots** live in `assets/img/work/` as WebP in two widths (`<name>-1600.webp`, `<name>-800.webp`). A project in `src/content.js` opts in with an `image` object (`src`, `src800`, `width`, `height`, `alt`); `pages.js` renders it as a card image on the home page and a browser-framed figure on `/our-work/`, using `srcset` plus explicit width/height to avoid layout shift. The ZimTribes shot was cropped from a client-supplied screenshot (browser chrome removed) with `sharp`, which is not a repo dependency; install it outside the repo if you need to make another.
- **One stylesheet and one dependency-free script**: `assets/css/main.css` (design tokens in `:root`) and `assets/js/main.js` (mobile menu, scroll reveal, form status banner). System fonts only, no third-party requests. Reveal animation is gated on a `js` class set inline in `<head>` and is disabled under `prefers-reduced-motion`.
- **Contact form flow**: `contact-us/index.html` posts to `contact-us/send.php`, which validates, then saves to a `website_enquiries` table (auto-created; MySQL or SQLite via PDO with prepared statements) and/or emails the team with `mail()`. It succeeds if *either* works and only reports an error if both fail. It always redirects back with `?sent=1` or `?error=<code>`, and `main.js` turns those into a message using a fixed whitelist of codes. Spam defences: same-site Origin/Referer check, honeypot field, a too-fast-submit check using the `t` timestamp set by JS, and a 5-per-hour-per-IP limit stored in the system temp dir. **The option lists are duplicated**: `formServices`/`formBudgets` in `src/content.js` and `NT_SERVICES`/`NT_BUDGETS` in `send.php` must be kept in step (the `service` column is `VARCHAR(20)`, so keep keys short).

- **Secrets**: settings live in `config.php` at the web root (copy `config.sample.php`; it is git-ignored and blocked by `.htaccess`). Never commit real database credentials or paste them into docs.

## Deployment notes

- Upload the repo root, but not `src/`, `tools/`, `.git` or `node_modules` (harmless if uploaded, since `.htaccess` returns 404 for them, but unnecessary). Create `config.php` on the server by hand.
- `.htaccess` sets the 404 page, blocks config/notes/source paths, adds basic security headers and long cache lifetimes for CSS/JS/images. If the site returns a 500 after an upload, rename `.htaccess` first.
- The live server previously served this repo's root while having no WordPress; a WordPress theme uploaded there blanked the whole site. Do not reintroduce WordPress theme files at the root.
- The old mirror's `submitform.php` files contained a hard-coded remote database password that remains in git history and on GitHub. That password should be treated as exposed and rotated.
- The original logos are `assets/img/brand/neucent-logo.png` and `circle_neucent_logo.png`; the site does not load them (it uses an inline SVG mark). Do not reuse `ong-logo.png` or the `logo*.svg` files from the old mirror; those belonged to another company and a purchased template.
